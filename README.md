# TilesSurviveMap

Бот-парсер карты игры Tiles Survive. Ищет союзы и игроков по штатам
через захват экрана ПК-клиента + OCR. Данные вытаскиваем ТОЛЬКО из того,
что игра сама рисует на экране. Сетевой протокол игры зашифрован — его
не трогаем принципиально.

## Что делает
- Находит нужный штат, объезжая карту и читая номер штата с экрана.
- Собирает поселения игроков (тег союза + ник + координаты).
- Считает скопления домиков (где союз РЕАЛЬНО сидит, а не где его земля).
- Рисует карту штата: подложка земель + точки игроков + тепловая карта.
- Отдаёт результат в Telegram.

## Ключевые решения (согласовано)
- Клиент: ПК-версия, на личном компе (НЕ на сервере — одна игровая сессия,
  nano VPS не тянет 3D, риск бана).
- Якоря на экране: HUD `X:Y` (позиция камеры) + `Штат #NNN` (текущий штат).
- Управление камерой: эмуляция мыши (штатного ввода координат в игре нет).
- Три профиля зума:
  1. дальний — навигация, поиск штата (читаем номер + границы зон);
  2. средний (~2/3) — основной сбор поселений (OCR ников);
  3. близкий (max) — добор при грязном OCR + карточки игроков для сводки.
- Два слоя данных (НЕ связаны жёстко):
  - слой Б (ГЛАВНЫЙ): домики игроков + их скопления (реальное расположение);
  - слой А (подложка): цветные зоны владений (номинальная принадлежность земли).
- Fallback при грязном OCR: сначала бот сам приближает камеру (зум 3),
  человека дёргаем только в крайнем случае.
- Геометрия штата (форма + решётка плиток) ПОСТОЯННА во всех штатах.
  Калибруем один раз, дальше живём на сохранённой модели.
  Переменное — цвета, владельцы, домики.
- Привязка координат — к ОКНУ игры, не к экрану/монитору. Окно может быть
  на любом из трёх мониторов. Бот сам приводит окно к эталонному размеру.
- Защита от смены разметки: перед сбором сверяем 2-3 опорные плитки с
  эталоном. Не совпало — СТОП + уведомление (возможно обновление игры).
- Архив запросов: данные протухают (поселения переезжают). Храним с датой,
  при повторном запросе предлагаем архив или свежий прогон.

Git — хранилище кода и версий: пишем локально, пушим в репу.

## Обработка запроса от бота (нормализация)
- Регистр ИГНОРИРУЕМ во всех типах запросов (штат, союз, игрок).
- Поиск штата: только цифры (#NNN), язык/регистр не важны.
- Поиск союза / игрока: буквы РАЗНЫХ алфавитов — латиница, кириллица,
  немецкий (умляуты), возможен китайский/иероглифы. Сравнение должно быть
  юникод-устойчивым, не наивным ASCII.
- Если точного совпадения НЕТ: не возвращаем пусто. Уведомляем и показываем
  список похожих найденных вариантов (fuzzy, расстояние Левенштейна),
  из которых пользователь выбирает.
- На будущее (модуль analyzer): учитывать «визуальных двойников» из-за
  грязного OCR — O/0, кир.О/лат.O, l/I/1 — при fuzzy-сравнении ников.

## Сессия 2026-10-09 — работа с окном и первый живой тест
Решения:
- Работаем ТОЛЬКО с живым окном. Старые скрины (пересохранялись в webp) —
  лишь референс раскладки, не для калибровки.
- Обязателен DPI-awareness (SetProcessDpiAwareness) ДО любой работы с окном,
  иначе координаты/скриншот едут (проверено: без него top=1017, с ним =12).
- Эталон окна: бот сам подгоняет РАЗМЕР и ПОЛОЖЕНИЕ окна (у игры нет кнопки
  «развернуть»). Текущий рабочий размер ~1774x1028 — кандидат в эталон.
- Два режима игры: «поселение» (город) и «карта». На карту пользователь
  переключается ВРУЧНУЮ перед запуском бота — бот за переключение не отвечает.
- Инет тормозит, данные грузятся с сервера → паузы на прогрузку после каждого
  движения камеры и перед снимком. Бот не спешит.
- Структура данных: data/<штат>/screens/ + результаты обработки. По завершении
  скрины удаляются (если не нужны), остаются карты/результаты.
- UI-маски: из OCR исключаем верхний бар окна, нижний чат, правую панель,
  миникарту. Применяется на всех зумах.
- Зумы тестируем по очереди: дальний → средний → близкий.

Результаты теста (дальний зум, режим карты):
- Захват окна: DPI-корректный, пиксель-в-пиксель. OK.
- OCR номера штата (левая плашка): читается ЧИСТО ("Штат #720" -> 720). OK.
- OCR объектов слоя А: найдены почти все плашки [TEG]Объект, теги верны;
  мусор от UI (чат/панель/миникарта) и текстур — лечится UI-масками.
- Движок: easyocr(ru+en), CPU. Инструменты: pygetwindow, PIL.ImageGrab.
- Зум out (отдаление) ботом — ОТЛОЖЕН (эмуляция мыши, следующий шаг).

## Права и запуск от админа (важно!)
- Игра (процесс tspc, Unity, окно класса UnityWndClass) запущена ОТ АДМИНА.
  Поэтому управление её окном (ресайз/перемещение) и будущий ввод мышью
  требуют, чтобы наша автоматизация тоже была от админа.
- Решение: служебная задача Windows **TSM_AdminRunner** (/RL HIGHEST).
  Запуск через `schtasks /Run /TN TSM_AdminRunner` — БЕЗ UAC (разово
  зарегистрирована из-под админа, admin_bootstrap.py).
  - Целевой скрипт пишем в admin_cmd.txt, вывод читаем из admin_result.txt.
- Поиск окна игры: СТРОГО по классу UnityWndClass + заголовок TilesSurvive
  (иначе цепляется своя python-консоль, т.к. её заголовок = путь с
  "TilesSurviveMap").

## Пункт A — ВЫПОЛНЕНО
- window_manager.ensure_window(): приводит окно к эталону 1774x1028 И вгоняет
  целиком в рабочую область монитора (reposition). Проверено на игре, кадр
  полный, без обрезки.
- Эталон окна: 1774x1028.

## Калибровка мыши (эмуляция ввода) — РАБОТАЕТ
- Синтетический драг (ctypes SetCursorPos + mouse_event) доходит до игры
  (при запуске от админа через TSM_AdminRunner).
- Пан карты ~1:1 к курсору: драг -400px -> контент -407px (k≈1.02),
  горизонталь без вертикального увода. Проверено сдвигом объекта [BDS]Городок.
- Вывод: шаг растрового обхода = нужный сдвиг в пикселях / k.
- Старт обхода (по решению): сначала задать зум (максимум, затем фикс. шагов
  внутрь для читаемости) и стартовый угол диаманта; затем серпантин.
- Фикс позиции окна: ETALON_POS = (-1774, 20), всегда этот монитор.

## Решения по обходу (сессия 2026-10-09, продолжение)
- Детерминированный старт подтверждён: клик "Мое поселение" -> макс.зум ->
  OCR штата == 720 (мы гарантированно в своём штате). Клик-ввод тоже доходит.
- Стартовая точка обхода = НИЖНИЙ ЛЕВЫЙ угол диаманта штата, от него серпантин.
- Фокус-гвард: перед КАЖДЫМ вводом активировать окно игры и проверять, что
  оно foreground (GetForegroundWindow == hwnd игры), курсор над картой.
  Пользователь может случайно увести фокус -> зум/драг уйдут не туда.
- Архитектура (СПЛИТ): повышенный процесс (TSM_AdminRunner) = ТОЛЬКО
  управление+захват (окно, мышь, скролл, скриншоты; границы штата — cv2/облака).
  OCR + сшивка + отрисовка — отдельным ОБЫЧНЫМ процессом (easyocr в
  админ-контексте тормозит ~90с на старте, в обычном — нормально).
- Калибровка шага мыши — СВОЯ на каждом из трёх зумов (пан может отличаться).
  Пока откалиброван дальний (макс) зум: k≈1.0.
- Направления: чтобы сдвинуть ВИД к нижне-левому углу — тащить карту вверх-вправо
  (вид едет в сторону, противоположную драгу).

## Стартовая механика — РАБОТАЕТ (проверено на живом переходе 831->720)
driver.py — безопасный ввод + навигация:
- ensure_focus: жёсткий захват переднего плана (AttachThreadInput+Alt), вытаскивает
  игру вперёд даже из-под активного окна. Без этого activate() не пробивает
  блокировку фокуса Windows.
- Фокус-гвард: _guard() перед каждым суб-действием; потеря фокуса -> FocusLost,
  ввод прерывается (не летит в чужое окно).
- АВАРИЙНЫЙ СТОП: ScrollLock (вкл) -> abort_requested()=True -> Aborted, бот встаёт,
  отпускает кнопку мыши, перестаёт грабить фокус. Выкл ScrollLock -> снова работает.
- clear_popups(): Esc x3 — гасит случайные модалки (рейд-инвайты и пр.).
- safe_drag/safe_click/safe_wheel/safe_key — весь ввод только через фокус-гвард.
- find_return_button(): детект кнопки 'Предпросмотр штата' по ОПАКОВОЙ круглой
  иконке (Hough-круг по синей маске + проверка 'синее кольцо >0.45 И центр <0.35').
  НЕ по тексту/стрелке (они полупрозрачные -> ложняки). Клик — по центру иконки.
- goto_own_state(): макс-зум; пока видна иконка возврата (мы в чужом штате) — клик;
  нет иконки = мы дома. Алгоритм старта (по Sanya): зашёл -> макс-зум -> проверить
  штат; ==720 дома; иначе кнопка возврата -> повтор -> дома -> искать угол.
- TODO старта: финальная сверка номера штата ==720 (OCR офлайн/плашка) после возврата.
- Наблюдение: у соседних штатов раскладка зон может отличаться (возможно ~2 варианта
  карты) — пригодится для шаблонов слоя-А при отрисовке.

## start_position() — РАБОТАЕТ (шаги 1-6 алгоритма Александра)
Проверено на живом прогоне (окно 981x799 -> эталон, чужой штат -> дом -> угол):
1. размер окна -> ensure_window
2. позиция окна -> ensure_window (ETALON_POS)
3. макс-зум (zoom_max до упора)
4. проверка штата: find_return_button (иконка кнопки возврата = чужой штат)
5. наш штат: тык по левому углу ромба миникарты MM_LEFT_CORNER=(1620,108) -> прыжок в угол
6. чужой штат: goto_own_state (вернуться) -> затем как п.5
   + проверка по границам (_pan_to_boundary влево/вверх по плашке-дифф) = доводка до угла.
Детект границы в процессе пана — ТОЛЬКО по плашке штата (_state_plate), НЕ по
синим кругляшам (ложняки) и НЕ по кнопке возврата.
Наблюдение: ромб миникарты есть и в чужих штатах -> стартовую точку можно брать
в любом штате (пригодится для обхода чужих штатов).

## Слой А штата — РАБОТАЕТ (сессия 2026-10-11)
Карта штата 720 = тип 1 (57 плиток: кольца 7:1, 6:3, 5:5, 4:8, 3:10, 2:14, 1:16). Шаблон: assets/reference/map_type1_v2.json.
Позиционирование: клики по миникарте (абсолютно, дрейфа нет; drag-панорамирование ненадёжно — ~20% дрэгов не срабатывают).
Цвета плиток НЕ владельцы (оранжевый = ZOV/SUN/FNX и т.д.) — владелец = тег из бейджа "N [TAG]Название", цвет хранится отдельно.

Порядок работы (игра запущена, штат 720, руки с мыши убрать, стоп = ScrollLock):
1. Съёмка (от админа, через планировщик TSM_AdminRunner): admin_cmd.txt -> src\crawl_mm.py
   -> data\720\scans\scan_<время>\{frames,journal.json}   (31 точка, ~3 мин)
2. Обработка (ОБЫЧНЫЙ процесс, нужен easyocr): python src\layer_a_process.py --journal <scan>\journal.json [--dry]
   SIFT-склейка по журналу, красные/синие бейджи, easyocr, голосование тегов по кадрам, привязка к плиткам (Hungarian по углу),
   тег Аркадии из подписи в центре, запись скана в data\720\layer_a.sqlite (scans, cell_owners), diff с прошлым сканом,
   recheck_<время>.json (слабые плитки), картинка карты.
3. Досъёмка слабых вблизи (4 щелчка зума): src\recheck_zoom.py (точки из data\720\recheck_none.json) -> <scan>\frames_zoom, journal_zoom.json;
   повторная обработка (п.2) подмешивает эти кадры как доп. голоса.
4. Картинка из БД без OCR: python src\render_scan.py [--scan ID]  (рендер: src\render_template.py, пастельные цвета + легенда).
Вблизи (4 щелчка) бейджи остаются и крупнее ~1.3x, но полный обход вблизи не нужен.
БД: scans, cell_owners(scan_id,cell_id,ring,tag,r,g,b,confidence,votes,source), cells, states, map_types, views v_latest_owners / v_owner_changes.
Не сделано: тип 2 (шаблон не перерисован), слой Б (домики игроков), Telegram-бот, автодетект R6-01-подобных промахов привязки вблизи.

## Схема разметки штата 720 (ЗАФИКСИРОВАНА, v12, 2026-10-12)
- Файлы: `assets/reference/map_schema_720.sqlite` (рабочая БД), `map_schema_720.json` (золотая копия) +
  `map_schema_720.sha256`. Старая версия: `assets/reference/old_v1/`. Картинка: `data/720/schema_v12_720.png`.
- 57 земель, фиксированные номера 1..57 (1 = Аркадия, дальше кольца 6→1) и имена: Аркадия, Военная база,
  Центр исследований, Мегаполис, Городок, Завод, Деревня; уникальное имя `title` = «Завод 7», «Деревня 12»;
  `code` = R<кольцо>-<NN> (это же cell_id в layer_a.sqlite). 63×63 блока по 20×20 клеток; 3666 блоков суши.
- Измерены тапами: земли 1, 31, 34, 39, 41. Сверены со скринами игры: центр + нижний, левый, верхний углы.
  НЕ проверены: правый угол и длинные стороны внешнего круга (границы там ±1 блок).
- Геометрию БД защищают 9 триггеров + хэш в `meta` + sha золотого JSON: правка земель/блоков/имён даёт ошибку,
  `import map_schema` падает, если JSON тронут. Менять можно ТОЛЬКО `plates.owner_tag` (+owner_updated/source/scan_id;
  история в `plate_owner_history`) и `sector_status`.
- Владельцы: `python src/map_schema_lock.py owners [scan_id]` (из layer_a.sqlite), или `map_schema_lock.set_owner(num, tag, source)`.
  Проверка целостности: `python src/map_schema_lock.py verify` (запускать перед боевым прогоном).
- Исправить схему осознанно = новая версия золотого JSON + НОВЫЙ файл БД, старый не трогать.
- Заметка: из Linux-песочницы Claude sqlite на примонтированной папке не открывается (disk I/O) — БД собирали во
  временной папке и копировали; на Windows всё работает штатно.
